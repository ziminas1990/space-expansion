# SES-209: Port the TypeScript flight-plan algorithm into the Python SDK

## Background

Both SDKs can build a flight plan that takes a ship from one kinematic
state to another. The TypeScript planner is simpler, and its tests
reliably pass. The Python planner is a different, larger design: its
unit tests skip known-bad cases and allow a fraction of intercepts to
fail.

Python should use the same planner as TypeScript. We are not going to
change TypeScript to match Python.

## Require

- Replace the Python flight-plan builder with a port of the TypeScript
  one.
- Replace the Python unit tests with a port of the TypeScript tests.
- Make Python's intercept entry points mean the same thing: intercept a
  ballistic target.
- Add the time-window and delta-v-window planners that TypeScript
  already has.
- Drop the Python-only planner.
- Leave plan execution (sending thrusts to the engine) and the
  TypeScript SDK alone.

## Acceptance

- A person can build an intercept in Python the same way as in
  TypeScript, including “take at least this long” and “spend about this
  much delta-v”.
- Random cases land on the target with no skipped seeds and no allowed
  failure rate.
- The old Python planner is gone.
- Following a plan against a live server still works.
- TypeScript is unchanged.
