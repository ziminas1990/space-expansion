# SES-220: Harvester recovers a stuck cargo port and returns when already full

## Background

After a Harvester restart the warehouse cargo port is often still open on
the server, but the new process does not know its id or access key. Every
miner that comes home then fails to open a port (`PORT_ALREADY_OPEN`) and
cannot unload. The fleet keeps mining and flying back into the same
failure.

A restarted miner can also already be sitting on a nearly full hold from
the previous run. Today it still flies out to an asteroid first. That
wastes a trip and can leave it unable to mine because there is no space.

## Require

Change Harvester mining so unload and the start of a ship cycle tolerate
leftover state from a previous run.

- If opening the warehouse receive port fails because a port is already
  open, close that port and open a new one, then unload as usual.
- At the start of a new control cycle for a mining ship, if its cargo is
  already more than 80% full, skip the asteroid and go to the warehouse
  to unload.

## Acceptance

- After a Harvester restart, miners that reach the warehouse unload
  successfully even if the warehouse port was left open by the previous
  process.
- A mining ship whose hold is already more than 80% full at the start of
  a cycle goes to the warehouse and unloads without visiting an asteroid
  first.
- A mining ship below that threshold still goes to an asteroid, mines,
  then returns and unloads.
- Unload still fails only when closing or reopening the port does not
  succeed, not on the first `PORT_ALREADY_OPEN` alone.
