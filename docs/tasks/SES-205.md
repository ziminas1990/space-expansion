# SES-205: Bind administrator interfaces to sessions instead of demuxing by payload type

## Problem

The game protocol routes traffic by `spex.Message.tunnelId`: login yields a root
session, `ICommutator.open_tunnel(slot)` binds a child session to one module,
and later messages on that id belong only to that module.

The privileged protocol does not. `admin.Message` carries a `token` for
authentication, and `AdministratorPanel` multiplexes `SystemClock`, `Screen`,
`Spawn`, and `BasicManipulator` through a single UDP session by switching on
`Message.oneof`. Clients therefore need a type demux (Python `Demux`,
TypeScript `lowlevel.Administrator` queues). Consequences:

- Routing is a special case, not the same session machinery as the game SDK.
- Each interface has one in-flight queue. A long `proceed_ticks` blocks
  `time_req` on the same type.
- There is no session close/heartbeat contract for privileged traffic.

## Goal

Give the administrator channel the same session model as the game channel:
open a session by **interface name**, receive a `session_id`, and route every
later message by that id. Payload-type demux on the client goes away.

Administrator interfaces stay a closed, static set. This is not `ICommutator`:
there are no slots, `ModuleInfo`, attach/detach events, or monitoring.

## Proposed behavior

1. **Access stays outside named sessions.** Login is still sent with no token
   (or token `0`) on the UDP persistent session. On success the server returns
   a token as today. That UDP session is the root for opening child sessions.
   Do not expose Access as a session named `"access"`.

2. **Root opens named sessions.** After login the client sends `open_session`
   with a well-known interface name and gets back a `session_id` (or a failure
   status). Unknown names fail. The server binds that id to exactly one
   handler (`SystemClock`, `Screen`, `Spawn`, or `BasicManipulator`).

   Well-known names match the current `Message` field names:

   - `system_clock`
   - `screen`
   - `spawn`
   - `manipulator`

3. **Several sessions per name are allowed.** Two `open_session("system_clock")`
   calls yield two ids. `proceed_ticks` on one session must not block
   `time_req` on another.

4. **Envelope carries `session_id`.** Add a field analogous to
   `spex.Message.tunnelId` (name it `session_id` or reuse `tunnelId` — pick one
   and use it consistently in proto, server, and SDKs). `session_id == 0` is
   the root: Access and `open_session` only.

5. **The `oneof` remains.** Protobuf still needs a body type. After bind, the
   server rejects a payload that does not match the session's interface (and
   `ISessionControl`). Clients already know the type from the open call, so
   they route by id, not by `oneof`.

6. **Session control.** Reuse the game `ISessionControl` contract on every
   child session: `close` / `closed_ind`, and heartbeat if privileged traffic
   needs the same liveness rules as game tunnels.

7. **Auth.** Keep checking the login token on root messages. Child sessions
   inherit the parent UDP session's authorization; they do not need a second
   login. Whether the token is still copied onto every child envelope is an
   implementation choice, as long as an unauthenticated client cannot open or
   use child sessions.

### Sketch (illustrative, not a field-number freeze)

```protobuf
message IAdminSession {
  oneof choice {
    string open   = 1;  // interface name
    uint32 opened = 21; // session_id
    Status failed = 22;
  }
}

message Message {
  uint32 session_id = 1;  // 0 = root
  uint64 token      = 2;
  uint64 timestamp  = 3;

  oneof choice {
    Access           access       = 5;
    IAdminSession    session      = 6;
    ISessionControl  control      = 7;  // or import/share the game one
    SystemClock      system_clock = 8;
    Screen           screen       = 9;
    Spawn            spawn        = 10;
    BasicManipulator manipulator  = 11;
  }
}
```

`IAdminSession` is a new root-only interface. Do not fold open/close into
Access.

## Compatibility and migration

This is an intentional wire break. Privileged clients in this repository
(Python SDK, TypeScript SDK, C++ ClientSDK, `admin_tool`) must move together
with the server. Do not keep a type-demux fallback on the new protocol.

Existing `token`-only envelopes without `session_id` are invalid after the
change.

## Scope

- `server/Privileged.proto` — `session_id` on `Message`, `IAdminSession` (or
  equivalent), session-control messages, reserved numbers/names if fields move.
- `server/AdministratorPanel` — session table (`session_id` → interface
  handler), `open_session`, reject mismatched payloads, close/heartbeat.
- C++ ClientSDK privileged pipe/session helpers and administrator functional
  tests.
- Python SDK: drop `Demux`; open a session per privileged interface; keep
  `Administrator` as an aggregator of session-backed clients.
- TypeScript SDK: `login_as_administrator` yields a root; each midlevel
  client (`clock`, `spawner`, `manipulator`, later `screen`) opens its own
  session(s) and uses session-id routing like game `Session`. Remove the
  lowlevel type demux.
- Tests that use the administrator clock, spawn, or manipulator.
- Privileged protocol documentation if/when it exists next to `docs/API.ru`.

## Out of scope

- Merging privileged traffic onto the game UDP port or into `spex.Message`.
- Reusing `ICommutator` or inventing slot ids for admin interfaces.
- Discovering the interface list from the server (the name set is well-known).
- Highlevel game entities wrapping administrator APIs.
- Changing the semantics of `SystemClock`, `Spawn`, `BasicManipulator`, or
  `Screen` request/response bodies, except as required to sit on a session.

## Acceptance criteria

- After login, `open_session("spawn")` returns a nonzero `session_id`.
- Messages on that id are handled only by Spawn; a `SystemClock` body on it
  is rejected.
- `open_session("nope")` fails without allocating an id.
- Two sessions with the same name are independent: in-flight work on one does
  not consume replies meant for the other.
- Client SDKs route privileged replies by `session_id`. Python `Demux` and the
  TypeScript administrator type-demux are gone.
- Closing a child session does not drop the authenticated UDP root session or
  sibling child sessions.
- Access login still works without a named session.
- Server, C++ autotests, Python tests, and TypeScript SDK tests that use the
  administrator interface pass.
