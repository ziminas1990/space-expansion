# SES-225: Thrust report names when the current vector ends

## Background

`thrust_req` answers with the force the engine is applying right now: the
components and the magnitude. It does not say how long that force will last.

`change_thrust` does set a duration. The server counts it from the moment the
command is applied, in ingame time, and then sets the thrust to zero. That
deadline stays on the server. A client that did not send the command, or that
no longer remembers it, cannot tell whether the engine is about to cut thrust
or will keep pushing. A later zero report only says that the cut has already
happened.

## Require

Extend the thrust report so that, together with the applied force, it names
the ingame time until which that vector stays set.

That time is the end of the duration of the `change_thrust` currently in
effect, counted from the moment the server applied the command. A later
`change_thrust` replaces both the vector and that time.

When no timed thrust is in effect, the report still describes the current
vector and does not name a future end. That is the case when:

- the duration has already passed;
- the thrust was set to zero.

`monitor` delivers the same thrust report, so it carries the same time.

## Acceptance

- While a timed thrust is in effect, `thrust_req` returns the applied force
  and the ingame time at which that force stops.
- That time is the apply moment of the current `change_thrust` plus its
  duration. A command delayed by a future timestamp starts its duration when
  it is applied, not when it was sent.
- A later `change_thrust` changes both the reported vector and the reported
  end time.
- After the duration ends, or after a `change_thrust` that sets the thrust to
  zero, the report shows a zero force and no future end time.
- A monitoring session's thrust reports include the same end time.
