# SES-231: Remove the Python SDK

## Background

The server has two client SDKs. The TypeScript SDK is the one in active use:
it has the client library, demo clients, and tests that talk to a built
server. The Python SDK is the older stack. It still contains the client
library, demo clients, its own unit tests, and the integration tests that
drive the server from the repository root.

The Linux and Windows build guides tell a person to create a Python virtual
environment, install the Python SDK's dependencies, and run those integration
tests. A second client is a second place to update when the protocol changes,
and the published way to check the server is the stack being retired.

Python stays on the machine because Conan, which builds the C++ server, is
installed with it. That use is separate from the SDK.

## Require

Remove the Python SDK from the project. That includes:

- the client library;
- demo clients written against it;
- unit tests and integration tests written against it;
- generation of Python protobuf bindings.

Where documentation tells a person to run the Python integration tests, tell
them to run the TypeScript SDK tests instead.

Documentation and contributor instructions that exist only to develop or run
the Python SDK are removed with it. Closed tasks stay as they are.

The C++ build still installs Python so that Conan can be installed.

## Acceptance

- The repository has no Python client SDK, no Python demo client, and no
  Python tests of the client or the server.
- The Linux and Windows build guides, in the section that used to run Python
  integration tests, tell the reader to run the TypeScript SDK tests.
- Those guides still install Python so Conan can build the C++ server.
- Living documentation describes the TypeScript SDK as the client library,
  including its demos and its tests.
- Closed tasks are unchanged.
