# SES-230: Fly the TypeScript harvester on IHoverEngine

## Background

The TypeScript harvester flies by setting a thrust vector on the engine.
That equipment is now RCS. The main engine, IHoverEngine, thrusts only
along the nose, and the ship turns with a rotate command.

A flight planner already builds this kind of flight: turn to a direction,
then burn along the nose for a computed time. The harvester does not use
it yet.

RCS still has the maximum thrust the old engine had. Once these flights
use the main engine, that strength is no longer what the hull thrusters
should have. This is the fourth step of [EPIC-1](../epics/EPIC-1.md).

## Require

Rewrite the TypeScript harvester's navigation so a flight to a destination
uses the ship's rotate command and IHoverEngine, as computed by the
existing flight planner.

Lower the RCS maximum thrust. The thrust those flights use moves to the
hover engine. RCS is not used to fly those legs. Mining, unloading, and
the rest of the harvester stay in place.

The protocol documentation describes RCS as the low-power system and
states the reduced maximum thrust.

## Acceptance

- On a flight, the harvester turns the ship with the rotate command, then
  thrusts with IHoverEngine along the nose.
- The turn and the burn are the ones the flight planner produces for that
  ship's mass, orientation, maximum rotation speed, and the hover engine's
  maximum thrust.
- The ship arrives and still mines and unloads afterwards.
- Those flights do not use RCS for their acceleration.
- The hover engine's maximum thrust is the value RCS had before this
  change, and the flight uses that thrust. RCS maximum thrust is lower
  than that.
- The protocol documentation states the reduced RCS maximum thrust.
