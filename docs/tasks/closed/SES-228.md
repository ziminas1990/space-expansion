# SES-228: Rename IEngine to IRCS

## Background

The engine interface sets a thrust vector in any direction and can change
that vector at once. That is a set of thrusters fixed around the hull, not
a main engine.

Those thrusters keep the strength the engine has today. Clients that
already fly by choosing a thrust vector keep that logic. They only need
the new name. This is the second step of [EPIC-1](../epics/EPIC-1.md).

## Require

Rename the engine interface to IRCS. The module type becomes RCS.

The contract stays the one the engine has now. A client still sets thrust
by direction and magnitude, still reads the maximum and the current
thrust, and still receives thrust updates. In the current server
configuration the maximum thrust stays the value these thrusters have now.

The protocol documentation describes IRCS as thrusters built into the
hull. Working together, they produce the requested thrust in any
direction. The text presents them as the low-power system and states that
the current configuration still gives them their present maximum thrust.

Update the clients for the new name only. The same calls, the same thrust
values, and the same decisions about when to thrust.

## Acceptance

- A module that was an engine is of type RCS and speaks IRCS.
- Setting a thrust vector still accelerates the ship in that direction,
  up to the same maximum thrust as before the rename.
- A client that flew on the engine still flies the same way after the name
  change, including both harvesters. Its choices of direction, magnitude,
  and timing are unchanged.
- Clients find this equipment under RCS, including blueprint listings.
- The protocol documentation describes IRCS as the hull thrusters and
  states that their maximum thrust is unchanged in the current
  configuration.
