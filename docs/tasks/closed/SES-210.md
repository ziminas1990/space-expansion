# SES-210: Headless harvester client

## Background

`demo/` is a reference client built on PyQt5. It contains two layers of
logic that are currently coupled:

- **Control logic** — automatic resource mining (`RandomMining`), automatic
  ship construction (`build_more_miners`), fleet monitoring, and world state
  maintenance.
- **GUI layer** — the Qt main window, tactical map, controller, and any
  commands issued manually through the graphical interface.

There is no way to run the automation without launching the full Qt
application, and PyQt5 is an unwanted dependency for the SDK.

## Require

- Replace `demo/` with a new headless client at `python-sdk/demo/harvester/`.
- The new client contains only the control logic from `demo/`:
  - automatic resource mining loop,
  - automatic ship-building loop,
  - commutator monitoring that attaches newly spawned ships to the mining loop.
- Credentials are passed via config file or command-line arguments — no GUI
  login dialog.
- The client exits cleanly on SIGINT / SIGTERM.
- Remove the old `demo/` directory from the repository.
- Remove the PyQt5 dependency from the project entirely.

## Acceptance

- `python-sdk/demo/harvester/` can be launched from the command line with no
  display server available (e.g. inside a headless container).
- After launch the client mines asteroids and builds new ships automatically,
  matching the behaviour previously visible in `demo/`.
- PyQt5 is not imported anywhere in the repository and is not listed in any
  dependency file.
- The old `demo/` directory no longer exists in the repository.
