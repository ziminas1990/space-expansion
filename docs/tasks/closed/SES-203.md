# SES-203: Remove the unused CelestialScanner module

## Problem

`CelestialScanner` is implemented and exposed by the server and SDKs, and its
blueprints are attached to default ships. However, no current application flow
uses it: the demo and web client use `PassiveScanner`, while
`ICelestialScanner.scan` is called only by tests.

Keeping the module adds a second overlapping scanner API and requires server,
protocol, configuration, SDK, documentation, and test maintenance without
providing an active product capability.

## Goal

Remove `CelestialScanner` and `ICelestialScanner` from the project, including
all runtime wiring, default configuration, SDK APIs, tests, and documentation.

## Scope

- `server/Protocol.proto` — remove `ICelestialScanner` and the corresponding
  `Message.oneof` field. Reserve the removed field number and name to prevent
  accidental wire-incompatible reuse.
- Server module implementation, manager declarations, system-manager wiring,
  blueprint factory support, global-container checks, build entries, and C++
  ClientSDK support.
- Legacy `server/space-expansion.cfg` and Python server configurator
  blueprints/default ship module references.
- Python SDK interface, module wrapper, factory and lookup helpers.
- TypeScript lowlevel, midlevel, and highlevel implementations, exports,
  factories, and module-type declarations.
- Regenerated protobuf bindings and exports for all supported SDKs.
- CelestialScanner-specific functional and integration tests, including test
  setup that uses it only to locate asteroids for another module.
- API documentation and references that recommend `ICelestialScanner`.

## Migration

- Do not replace `CelestialScanner` with another module automatically.
  Default ships that already contain a `PassiveScanner` keep that module.
- Tests or examples that need asteroid discovery must use the supported
  discovery mechanism or receive the asteroid identifier from their fixture.
- This is an intentional API-breaking change: clients must stop requesting
  modules of type `CelestialScanner` before upgrading.

## Acceptance criteria

- `ICelestialScanner` is absent from the public protocol and its former
  `Message.oneof` number and name are reserved.
- The server no longer builds, registers, instantiates, or schedules a
  `CelestialScanner` manager or module.
- No default blueprint or ship configuration references `CelestialScanner`.
- Python and TypeScript SDKs expose no CelestialScanner classes, interfaces,
  helpers, factories, exports, or generated protocol symbols.
- Tests, demo, web client, and documentation contain no CelestialScanner
  references.
- Server and SDK builds and their remaining test suites pass.
