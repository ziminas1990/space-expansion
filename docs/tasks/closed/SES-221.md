# SES-221: English protocol documentation sufficient to implement a Harvester

## Background

The only player-facing protocol documentation is in Russian. It trails the
current protocol: login, sessions, and several module interfaces have
changed or appeared since those pages were written.

Protobuf names the fields. It does not explain how a client actually talks
to the server:

- the UDP envelope and session model;
- how a command pairs with a later reply or report;
- how a player finds ships, cargo, and asteroids in the world.

A person (or an agent) who wants a client in a new language should not
need this repository’s SDKs. The intended check is: take the English docs
and the game protobuf, put them in an empty project, and ask an agent to
write a Harvester — an autonomous miner that logs in, flies, extracts, and
unloads.

## Require

Replace the Russian protocol and module documentation with English
documentation of the game protocol.

The docs plus the protocol definition must be enough to implement a
client from scratch. Cover:

- how a client talks to the server (transport, envelope, login, sessions);
- every player-facing module interface, including behavior protobuf does
  not state: what a command does, what comes back, when it fails, how
  long jobs work;
- enough world shape to run a mining fleet: root commutator, ships,
  cargo, asteroids, warehouse.

Do not document this repository’s SDKs. The reader has only the docs and
the protobuf.

## Acceptance

- Player-facing protocol documentation is in English. The Russian module
  pages are no longer the source of truth.
- Every player-facing interface in the game protocol is documented with
  commands, replies, statuses, and the rules that protobuf does not
  carry.
- From the docs alone, a reader can log in, open a session to a ship
  module, and tell a request from a later unsolicited report.
- An agent given only those docs and the game protobuf can implement a
  Harvester-class client in a language of choice: log in, find mining
  ships and a warehouse, fly to an asteroid, mine, return, unload. It
  does not need this repository’s source or SDKs to do that.
- Documented commands and fields match the current protocol.
