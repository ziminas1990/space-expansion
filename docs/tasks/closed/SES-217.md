# SES-217: Package the TypeScript SDK as `@spx/sdk`

## Background

The TypeScript SDK is built like part of this repository rather than consumed
like a library. Its package is named `space`, its demos are compiled by the SDK
`tsconfig`, and the harvester reaches into SDK sources through relative imports
such as `../../highlevel/index.js`.

That arrangement hides packaging defects. A demo can use files that were never
exported, depend on the source-tree layout, or accidentally share dependencies
with the SDK. It does not exercise the same public boundary that an external
client would use.

## Require

Turn `typescript-sdk/` into an installable ESM package named `@spx/sdk`.
Publish JavaScript, TypeScript declarations, and explicit public entry points
for the supported SDK API. Consumers must be able to import the package and its
public highlevel subpaths through package specifiers such as:

```typescript
import { login, ModuleType } from "@spx/sdk/highlevel";
import type { Ship } from "@spx/sdk/highlevel/ship";
```

Convert `typescript-sdk/demo/harvester/` into a separate private Node
application with its own `package.json`, TypeScript configuration, dependency
installation, and build output. It declares `@spx/sdk` as a dependency and
uses only the SDK's package exports; it does not import SDK source files by
relative path.

The SDK and harvester build independently. Harvester dependencies do not
become SDK dependencies, and SDK compilation does not compile the harvester as
part of the library. Keep a command in `typescript-sdk/package.json` that lets
a developer start the harvester from `typescript-sdk/`.

How the repository connects the local harvester dependency to the local SDK
package is left open, but that connection must preserve normal external-package
resolution rather than source-path aliases.

## Acceptance

- The SDK package identifies itself as `@spx/sdk` and exposes JavaScript and
  declaration files through package exports.
- A clean consumer can install the packed SDK artifact, type-check an import
  from `@spx/sdk/highlevel`, and run code using that import without access to
  the SDK source tree.
- Supported highlevel modules can be imported through documented
  `@spx/sdk/highlevel/...` subpaths.
- The published SDK artifact does not contain compiled tests or demos.
- The harvester has its own private `package.json` and can install, build, and
  run as an application independently of the SDK build.
- Every harvester import of SDK functionality uses `@spx/sdk` or one of its
  exported subpaths. It contains no relative import into SDK source or build
  directories.
- Installing harvester dependencies does not add them to the SDK package's
  dependency list.
- `npm run harvester` from `typescript-sdk/` builds or otherwise prepares the
  required local packages and starts the converted harvester.
