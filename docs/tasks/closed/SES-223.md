# SES-223: One message for the full commutator module list

## Background

`all_modules_info_req` is answered by a separate `module_info` for each
occupied slot. Empty slots are left out. A commutator with no modules sends
nothing. The reply has no count and no final message.

A session is one ordered stream. The reply to the next command is whatever
message arrives next on that session. The client cannot tell that the list
has ended, except by waiting until messages stop. That wait is not a
completion signal:

- a late `module_info` is then read as the reply to the next command;
- that exchange fails;
- the session is dropped and cannot be reused.

`total_slots` does not close the gap. The number of `module_info` messages
is the number of installed modules. It can be smaller than `total_slots`,
and it can be zero.

## Require

Answer `all_modules_info_req` with a single `modules_info_list` that
contains every installed module.

- Each entry has the same fields as today's `module_info`.
- Empty slots are not included.
- A commutator with no modules still gets one message, with an empty list.
- After that message the same session can carry the next command. The
  client does not wait for silence to decide the list is finished.

## Acceptance

- A request for all modules returns exactly one message, and that message
  lists every installed module.
- Empty slots do not appear in the list.
- A commutator with no modules returns one message with an empty list.
- The same session can then run another commutator command and receive
  that command's reply, without opening a new session and without a
  silence timeout.
- A request for one slot still returns a single module description for
  that slot.
