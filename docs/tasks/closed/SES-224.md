# SES-224: One way to close a session

## Background

A session opened through the commutator can be closed in two ways:

- `ISessionControl.close` on that session;
- `ICommutator.close_tunnel` on the commutator session, naming the tunnel.

Both tear the session down the same way. The client gets `closed_ind` on
the closed session. The module that owned the session drops it. The
commutator does not keep a list of tunnels it opened, so `close_tunnel`
does not update any commutator state that `close` would leave behind.

The extra command still has its own reply, `close_tunnel_status`, and its
own documentation. Callers have to know which close to use.

## Require

Remove the commutator command that closes a tunnel, and the status reply
that belongs to it.

The only way to close a session, including one opened with `open_tunnel`,
is `ISessionControl.close` on that session. The client still learns the
session is closed from `closed_ind`. Opening a tunnel is unchanged.

Protocol documentation and the clients that speak this interface follow
the single close path.

## Acceptance

- The commutator interface has no command to close a tunnel and no status
  reply for that command.
- A session opened to a module is closed by session close on that session.
  The client receives `closed_ind`.
- After that close, the module can accept another session in the freed
  slot.
- Opening a tunnel still returns a new session id, or the same failure as
  today when the slot or the module rejects it.
- Protocol docs describe session close as the only way to close a session.
