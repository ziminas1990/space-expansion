# SES-222: Move heartbeat to the root session

## Background

Heartbeat sits on the common session-control interface, so every session
looks able to carry one. The server never uses it that way. It sends
heartbeat only on the root session, and only to tell whether the UDP
connection is still alive.

Clients still recognize and answer heartbeat on every session. That
logic does not belong there: keepalive is a property of the root
session, not of each device session. Leaving the message on the shared
interface keeps that special case in both the server and every client.

## Require

Move heartbeat from the common session-control interface to the root
session interface.

Keep today's keepalive behavior:

- the server still sends heartbeat only on the root session;
- continued silence from the client still closes the UDP connection;
- ordinary sessions no longer have a heartbeat message.

## Acceptance

- Heartbeat is a root-session message. The common session-control
  interface no longer includes it.
- A quiet client still receives heartbeat on the root session. A client
  that stays silent still loses the UDP connection, and each open
  session on it is closed.
- Neither the server nor a client has to treat heartbeat as a message
  that every session must forward or echo.
