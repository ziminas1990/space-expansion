# SES-232: IRCS thrusts at full force in a chosen direction

## Background

IRCS takes a thrust vector and a magnitude. A client can ask for any force
up to the maximum, and the thrusters produce that force.

The hull thrusters always push at their full force. The player chooses
only the direction in which that force is applied. The main engine is the
control for how hard the ship burns. This is the fifth step of
[EPIC-1](./epics/EPIC-1.md).

The protocol replaces the command that carried a magnitude. Clients move
with the server.

## Require

Change IRCS so a thrust command sets a direction and does not set a
magnitude.

- While the thrusters are running, the force is the module's maximum
  thrust, along the direction the player set.
- The length of the supplied vector does not change the force. The same
  direction always produces the same thrust.
- A zero vector produces no thrust.
- The thrusters still run for the commanded time, then stop. A later
  command replaces the current one.
- The maximum thrust value stays the one these thrusters have now.

The fields of the existing IRCS commands may be renumbered. Clients that
command RCS send a direction and no magnitude.

The protocol documentation describes the command as a direction and states
that the force is the maximum.

## Acceptance

- Setting a direction accelerates the ship in that direction at the
  module's maximum thrust. A longer or shorter vector in the same
  direction does not change the acceleration.
- A zero vector produces no acceleration.
- When the commanded time ends, the acceleration stops.
- The client can read back the applied thrust. Its magnitude is the
  maximum while the thrusters run, and zero when they do not.
- The specification still reports the same maximum thrust as before this
  change.
- Clients that command RCS send a direction and no magnitude.
- The protocol documentation describes the command as a direction and
  states that the thrusters produce their maximum thrust along it.
